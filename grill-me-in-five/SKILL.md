# Grill Me in Five

使用者會告訴你要加什麼功能。不要一開始就動手寫程式，也不要自己換成別的功能。先用五個問題把這個功能的細節問清楚，整理成計畫，等使用者同意後才實作。

## 步驟

### 1. 先看懂專案

先執行這個 Skill 資料夾裡的掃描程式，參數是專案根目錄（放 .xcodeproj 的那一層）。Skill 放在專案裡時，在專案根目錄執行：

```bash
bash .agents/skills/grill-me-in-five/scripts/scan.sh .
```

（Skill 放在別的地方，就把路徑換成這個 Skill 資料夾的位置。）

它會列出 Swift 檔案、畫面、資料型別和每筆資料記了哪些欄位。再挑需要的檔案讀，弄清楚這個 App 現在有哪些畫面、存了哪些資料、能做哪些事。這一步不要改任何檔案。

如果使用者沒有說要加什麼功能，先問他要做什麼，這一題不算在五題裡。

### 2. 問五個問題

問之前先讀 [references/questions.md](references/questions.md)，裡面有怎麼問、問題格式和例子。

- 一次只問一題，等使用者回答完再問下一題，總共剛好五題。
- 每一題都附上你推薦的答案，使用者可以直接回「照你的」。
- 使用者回答「都可以」或答得很短時，就用你推薦的答案，說一聲之後繼續下一題。
- 能從程式碼找到答案的事情，就自己去看，不要拿來問使用者。

五題的方向（依照這個順序，用使用者聽得懂的話問，並且根據要做的功能改寫）：

1. **什麼時候用**：使用者會在什麼情況下用到這個功能？
2. **在哪裡**：入口放在哪裡？是新的畫面、一個按鈕，還是原本畫面裡多一塊？
3. **長什麼樣子**：要顯示哪些東西？怎麼排、怎麼分組？
4. **資料**：要多記下什麼？（例如時間、次數）原本的資料要怎麼跟著改？
5. **例外和範圍**：沒有資料時顯示什麼？使用者反悔時怎麼辦？這次先做到哪裡為止？

### 3. 整理成計畫

五題問完後，用下面的格式整理，問使用者「這樣做可以嗎？」等他同意才繼續。他想改，就照他說的改完再問一次。

```text
要做：<功能名稱>
細節：
- <根據第 1～5 題的回答，一題一行>
會改到：<檔案1>、<檔案2>
這樣做可以嗎？
```

### 4. 實作

- 只用 SwiftUI，不加第三方套件。
- 改動越小越好，不要重寫原本就能動的程式。
- 改完執行編譯程式，確認沒有錯誤再回報：

  ```bash
  bash .agents/skills/grill-me-in-five/scripts/build.sh .
  ```

  看到 `BUILD FAILED` 就照它印出的錯誤修正，再跑一次。試了三次還是失敗，就停下來，把錯誤告訴使用者。
  如果它說「權限不夠」，代表是沙盒擋住了編譯，不是程式寫錯：向使用者要求執行權限後再跑，不要去改程式。

### 5. 回報

用三行交代：

1. 做了什麼
2. 怎麼試（在 App 裡點哪裡、看到什麼就代表成功）
3. 之後還可以怎麼延伸

## 規則

- 做使用者指定的功能，不要自己換成別的功能。
- 使用者同意計畫之前，不要改任何檔案。
- 問題一次一題，不要一次列出五題。
- 不要問可以從程式碼找到答案的問題。
