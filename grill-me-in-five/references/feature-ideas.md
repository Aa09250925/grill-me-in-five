# 怎樣才算「沒想到的功能」

提新功能之前讀這份。先用判斷標準檢查自己的點子，再參考後面的例子。例子只是給你抓感覺，不要直接照抄，要從使用者五題的回答裡找理由。

## 判斷標準

一個好的「沒想到的功能」要同時符合：

1. **不在常見清單裡**：不是新增、刪除、編輯、搜尋、排序、分類標籤、深色模式、推播通知。
2. **用到 App 已經有的資料**：例如建立時間、完成狀態、金額、順序、次數。不用使用者多輸入東西最好。
3. **跟回答有關**：說得出是哪一題的哪個回答讓你想到的。
4. **一個畫面內做得完**：只用 SwiftUI，不加第三方套件，改動不超過兩三個檔案。
5. **一句話講得清楚**：講不清楚就是太複雜，換一個。

不合格的例子：

- 「加上分類」：常見清單裡的。
- 「接上雲端同步」：要帳號和伺服器，一堂課做不完。
- 「用 AI 自動幫你排程」：講不清楚到底做什麼，也不是用 App 已經有的資料。

## To-Do App 的例子

| 功能 | 一句話 | 用到的資料 |
| --- | --- | --- |
| 今天只做三件 | 每天從清單挑三件放在最上面，其他的先收起來 | 順序、日期 |
| 拖太久提醒 | 放超過三天還沒完成的事變成橘色，問你要不要拆小一點 | 建立時間、完成狀態 |
| 連續完成天數 | 每天至少完成一件就加一天，斷掉就歸零 | 完成時間 |
| 你的黃金時段 | 統計你通常幾點完成最多事，顯示在最上面 | 完成時間 |
| 兩分鐘任務 | 標記「兩分鐘就能做完」的事，一鍵只看這些 | 新增一個布林值 |

## 記帳 App 的例子

| 功能 | 一句話 | 用到的資料 |
| --- | --- | --- |
| 今天還能花多少 | 設一個每日預算，首頁顯示今天剩下多少 | 金額、日期 |
| 這週第幾杯 | 同一個名稱這週出現第幾次，記帳時直接告訴你 | 名稱、日期 |
| 值得嗎？ | 每筆記完可以按「後悔」，月底看後悔的錢有多少 | 新增一個布林值 |
| 換算成便當 | 每筆金額旁邊顯示「等於幾個便當」 | 金額 |
| 最貴的一天 | 找出這個月花最多的一天，點進去看那天買了什麼 | 金額、日期 |

## 提出功能的格式

```text
我想做：<功能名稱>
一句話：<這個功能在做什麼>
為什麼：你在第 <幾> 題說 <回答>，所以 <理由>
會改到：<檔案1>、<檔案2>
要做這個嗎？
```
