# 怎麼問五個問題

問問題之前讀這份。目標是用五題把功能的細節問清楚，讓使用者做決定，而不是你自己猜。

## 好問題的樣子

- **一次一題**：問完等回答，再根據回答調整下一題。
- **附推薦答案**：每題最後加一句「我推薦：……」，讓使用者可以直接回「照你的」。
- **給選項**：能用二選一或三選一問，就不要開放式地問「你想要怎樣？」
- **用使用者的話**：不要出現程式名詞（State、Model、NavigationStack），改說「畫面」「按鈕」「記下來」。
- **問決定，不問知識**：程式碼裡查得到的（例如現在用什麼存資料），自己去看，不要問。

不好的問題：

- 「你希望這個功能有哪些需求？」：太空泛，使用者不知道怎麼回答。
- 「要用 @Observable 還是 @State？」：這是你該決定的技術細節。
- 一次列出五題：使用者會只回第一題，或全部回「都可以」。

## 問題格式

```text
第 <幾> 題（共 5 題）：<問題>
A. <選項>
B. <選項>
我推薦：<選項>，因為 <一句理由>
```

## 例子一：To-Do App「待辦附照片」

1. 什麼時候用？A. 拍黑板或作業單，記住要做什麼 B. 做完拍一張當證明。我推薦 A，因為大多數人是在抄作業的時候用到。
2. 入口放哪裡？A. 新增待辦時旁邊多一個相機按鈕 B. 點進待辦之後才加照片。我推薦 A，新增時順手就能拍。
3. 長什麼樣子？A. 清單上顯示小縮圖 B. 只顯示一個迴紋針圖示，點進去才看到。我推薦 A，一眼就知道哪件有附圖。
4. 資料：一件待辦可以附幾張？A. 一張 B. 很多張。我推薦 A，先做最簡單的。
5. 例外：照片刪掉或不給相簿權限時怎麼辦？我推薦：顯示原本的待辦，不顯示圖片，也不要跳錯誤。

## 例子二：記帳 App「每日預算」

1. 什麼時候用？A. 每次花錢前看一眼還剩多少 B. 晚上睡前檢查。我推薦 A。
2. 入口放哪裡？A. 首頁最上面直接顯示 B. 另一個統計頁。我推薦 A，不用多點一下。
3. 長什麼樣子？A. 「今天還能花 NT$ 120」一行字 B. 一條進度條。我推薦 A 加上超過時變紅色。
4. 資料：預算怎麼設定？A. 固定一個數字 B. 每天可以改。我推薦 A，在設定裡改一次就好。
5. 範圍：超支時要做什麼？A. 只變紅色 B. 跳提醒。我推薦 A，這次先不做通知。
